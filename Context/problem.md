# 문제정의서

## 1. 목적

내부망 사용자가 자신의 사건을 자연어로 설명하면, 서버에 등록된 소청 결정 문서에서 유사 사례를 찾아 사건번호, 사건내용, 결정 결과, 유사한 점과 다른 점, 원문 근거를 확인할 수 있게 한다. 검색 결과와 답변에 대한 사용자 평가를 모아 품질을 지속적으로 개선한다.

## 2. 확인된 운영 조건

- 서버는 특정 PC 한 대다. 알려진 사양은 RTX 5060 GPU와 시스템 RAM 32GB다. CPU 모델과 저장 공간은 아직 확인되지 않았다.
- 웹 사용자는 내부망에서 접속하며, 동시 접속자는 최대 20명이다.
- 개발 PC와 GitHub는 외부망에 있고, 실제 서버는 인터넷에 연결되지 않은 Windows 11 폐쇄망 PC다. 외부망에서는 공개·가상 자료만으로 개발·시험하며, 승인된 프로그램·설치 파일·공개 모델의 오프라인 묶음만 폐쇄망에 반입한다.
- 실제 원본 문서와 추출문·검색 색인·임베딩, DB, 사용자 질문·답변·평가, 평가 Excel의 승인본·변경 후보, 운영 로그·백업·비밀값은 폐쇄망에서만 생성·보관한다. 이 자료를 외부망 개발 PC나 GitHub로 반출하지 않는다.
- AI 답변 생성은 서버 전체에서 동시에 1건만 처리한다. 나머지 질문은 접수 순서대로 대기한다. 답변 완료까지 허용 가능한 최대 대기 시간은 정하지 않았다.
- <span style="color:red">대기 목록은 웹 화면 한쪽에 표시하고 새 질문은 목록 아래에 쌓는다. 사용자는 자신의 질문 내용과 상태를 확인할 수 있다. 다른 사용자의 질문은 대기 순서와 처리 상태를 알 수 있는 한 줄 요약만 표시하되, 이름·사건번호·연락처 등 개인정보와 민감정보는 제거하거나 가린다. 운영 전에 로그인 방식, 일반 사용자·관리자 권한, 원문 열람 범위와 요약 마스킹 규칙을 확정한다.</span>
- 운영 문서 형식은 HWPX와 PDF다. 개별 사건 문서와 여러 사건을 수록한 책자형 문서가 모두 들어온다. 문서는 수백 건이 될 수 있다.
- 암호가 걸린 문서에는 공통 암호가 적용된다. 암호는 Git에 포함되지 않는 서버 설정으로 관리한다.
- 관리자가 서버의 지정 폴더에 문서를 넣으면, 서버가 설정 파일의 지정 시각에 하루 한 번 새 파일을 검사하여 자동 등록하고 등록한 원본은 다른 보관 폴더로 옮긴다.
- 사용자는 검색·답변 결과의 적절성을 평가할 수 있어야 한다. 그 결과는 품질 개선에 활용한다.

## 3. 사용자가 해결하려는 문제

사용자는 사건의 조건을 알고 있지만, 비슷한 소청 결정이 어느 문서와 사건번호에 있는지 알기 어렵다. 예를 들어 “음주사건인데 인명사고는 없고 대물 사고만 있다”는 설명에서 관련 사례를 찾고, 어느 사실과 판단이 유사한지 원문으로 확인하고자 한다. 책자형 문서는 한 파일에 여러 사건이 담겨 있어 파일 단위 검색만으로는 정확한 사건을 찾기 어렵다.

## 4. 필요한 결과

1. 사건별 검색 결과: 사건번호, 사건내용 요약, 원처분 및 결정 결과, 유사점, 차이점.
2. 검증 가능한 근거: 답변의 주요 판단마다 원문 내용과 위치를 연결한다. 근거가 부족하면 확정적으로 표현하지 않는다.
3. 사용 가능한 대기 경험: 질문 접수 순서와 처리 상태를 볼 수 있고, 새 질문이 목록 아래에 추가된다.
4. 자동 문서 등록: HWPX와 PDF의 신규 등록, 중복 방지, 실패 상태 확인, 원본 보관.
5. 품질 개선: 사용자의 평가를 바탕으로 문서 추출 오류, 검색 순위, 답변 설명의 문제를 구분하고 개선 결과를 검증한다.

## 5. 범위와 원칙

- 서버의 지정 폴더를 통한 문서 등록을 기본 운영 방식으로 한다. 웹에서 문서를 직접 업로드하는 기능은 현재 요구사항에 없다.
- 책자형 문서는 목차·제목·사건번호·본문 구조를 이용하여 사건별로 분리한다. 모호하게 분리된 사건은 자동 등록 성공으로 단정하지 않고 확인 가능한 상태로 남긴다.
- 원문과 추출된 사건 데이터, 검색 색인을 구분해 보관한다. 검색용 요약은 원문의 대체물이 아니다.
- 사용자 피드백은 곧바로 모델을 재학습시키는 신호로 사용하지 않는다. 자동 개선안을 시험하고 기존 대표 질문에서 품질 저하가 없을 때 반영하며, 되돌릴 수 있어야 한다. 원문 자체의 오류는 평가만으로 임의 수정하지 않는다.
