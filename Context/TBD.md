## 2. 확인된 제약과 요구

### 확정

- 실제 서버는 Windows 11 폐쇄망 PC 한 대다.
- 서버 사양은 RTX 5060 GPU와 RAM 32GB이며 CPU와 저장 공간은 아직 확인하지 않았다.
- 운영 자료에는 개인정보와 민감정보가 포함된다.
- 실제 원본·추출문·검색 자료·임베딩·질문·답변·평가·로그·백업은 폐쇄망 밖으로 반출하지 않는다.
- BitLocker는 사용할 수 없다.
- 기관 계정 또는 Active Directory 연동은 사용할 수 없다.
- 계정과 보안은 기관 계정 연동이 아닌 애플리케이션 자체 기능과 Windows PC 운영 보안으로 나누어 검토한다.
- 현재 논의는 코딩 관점의 보안을 우선한다.

### 기존 요구 중 유지할 사항

- 최대 20명이 내부망 웹에 접속한다.
- AI 답변은 서버 전체에서 동시에 1건만 처리한다.
- 다른 사용자의 대기 항목에는 개인정보·민감정보를 제거한 한 줄 요약만 표시한다.
- 관리자가 질문·답변 보존 기간을 설정하고 기간 경과 후 선택 삭제 또는 익명화할 수 있어야 한다.
- 프로그램·DB·검색 색인·모델·백업은 폐쇄망에서 운용한다.

## 3. 애플리케이션 계정관리 제안

기관 계정을 사용할 수 없으므로 시스템 전용 계정을 두는 방안을 우선 검토한다.

| 항목 | 현재 제안 | 상태 |
| --- | --- | --- |
| 가입 | 임의 회원가입 없이 관리자가 계정 생성·비활성화 | 제안 |

| 비밀번호 | 복호화 가능한 암호문이 아니라 Argon2id 해시로 저장 | 제안 |
| 로그인 방어 | 실패 횟수 제한, 일정 시간 잠금, 로그인 감사 기록 | 제안 |
| 세션 | DB 기반 불투명 세션, DB에는 세션 토큰 해시 저장 | 제안 |
| 세션 쿠키 | `Secure`, `HttpOnly`, `SameSite` 적용 | 제안 |
| 세션 폐기 | 로그아웃·비밀번호 변경·계정 정지 시 즉시 무효화 | 제안 |
| 관리자 추가 인증 | 폐쇄망에서 동작 가능한 TOTP 또는 보안키 검토 | TBD |

공용 관리자 계정은 사용하지 않고 개인별 관리자 계정을 사용한다. 관리자 계정도 일상적인 DB 최고권한이나 Windows 관리자 계정과 분리한다.

## 4. 권한검사 제안

화면에서 버튼이나 링크를 숨기는 것으로 권한을 통제하지 않는다. 모든 API 요청에서 서버가 다음 조건을 직접 확인한다.

- 로그인 여부
- 일반 사용자 또는 관리자 역할
- 요청한 질문·답변의 소유자
- 원문 열람 권한
- 문서 등록·삭제, 평가 승인, 튜닝 변경과 보존·삭제 설정의 관리자 권한

일반 사용자는 자신의 질문 내용·상태·답변을 조회한다. 다른 사용자 항목은 마스킹된 요약·순서·상태만 조회할 수 있다. 관리자 원문 조회와 설정 변경은 모두 감사 기록을 남긴다.

## 5. 애플리케이션 암호화 제안

### 5.1 암호화 대상

다음 자료는 애플리케이션에서 인증된 암호화 방식으로 저장하는 것을 검토한다.

- 원본 HWPX·PDF
- 추출 원문과 구조화된 개인정보
- 사용자 질문·답변과 관리자 메모
- 평가자료와 별도 백업

현재 후보는 검증된 라이브러리의 AES-256-GCM이다. 자체 암호화 알고리즘은 만들지 않는다. 레코드나 파일별로 고유 nonce를 사용하고, 암호화 키 버전과 인증 태그를 저장한다. 레코드 ID와 데이터 종류를 AAD에 포함하는 방안을 검토한다.

### 5.2 비밀번호와 데이터 암호화의 구분

- 사용자 비밀번호는 Argon2id 해시로 저장하며 복호화하지 않는다.
- 문서·질문·답변은 필요할 때 복호화해야 하므로 대칭키로 암호화한다.
- 암호화 키는 소스, Git, `release/`, DB와 로그에 직접 넣지 않는다.

### 5.3 키 관리의 미결 사항

암호화된 데이터와 키가 같은 PC에 있고 애플리케이션이 자동으로 키를 읽으면, PC 또는 앱 실행 권한을 완전히 탈취한 공격자는 복호화를 시도할 수 있다. 반대로 서버 시작 때 관리자가 키를 입력하면 저장장치 탈취 방어는 강해지지만 무인 자동 재시작이 불가능하다.

다음 중 하나를 선택해야 한다.

1. 보안 우선: 재시작 후 관리자가 키를 입력하여 서비스 잠금을 해제한다.
2. 가용성 우선: 키를 Windows의 보호 저장소와 제한된 서비스 계정 권한으로 보관하여 자동 시작한다.
3. 별도 보안장치: 기관이 승인한 하드웨어 키 또는 외부 키 저장 수단을 사용한다.

키 생성·보관·교체·폐기·분실 복구와 기존 데이터 재암호화 절차도 함께 정해야 한다.

## 6. DB 전체 암호화에 대한 정리

DB 전체를 복호화해 RAM에 올리는 구조를 의미하지 않는다. 데이터 유형별로 다르게 처리하는 혼합 구조를 검토한다.

| 데이터 | 디스크 저장 제안 | 사용할 때 |
| --- | --- | --- |
| 질문 상태·대기 순서·문서 ID 등 운영 메타정보 | PostgreSQL의 일반 필드 | DB에서 직접 조회 |
| 질문·답변·추출 원문·식별정보 | 암호화된 DB 필드 | 필요한 레코드만 복호화 |
| 원본 HWPX·PDF | 암호화된 파일 | 열람·재처리 시에만 복호화 |
| 임베딩·BM25 검색 자료 | 암호화된 묶음 또는 암호화 필드 | 서비스 시작 후 RAM 검색 구조로 복호화하는 안 검토 |
| 사용자 비밀번호 | Argon2id 해시 | 복호화하지 않고 검증 |

전체 원문과 질문·답변을 RAM에 계속 둘 필요는 없다. RAM에는 검색에 필요한 임베딩 배열, BM25 색인, 문단·사건 ID와 최소 조건만 유지하고, 검색된 상위 문단만 필요할 때 복호화한다.

## 7. pgvector와 RAM 검색의 충돌

pgvector는 DB에 검색 가능한 벡터가 있어야 한다. 임베딩을 AES 방식으로 암호화하면 pgvector가 유사도 검색을 수행할 수 없다. 따라서 기존 `PostgreSQL + pgvector` 우선안과 `임베딩 암호화 후 RAM 검색` 제안은 동시에 그대로 적용할 수 없다.

### 선택안 A — pgvector 유지

- 임베딩을 DB에 검색 가능한 형태로 저장한다.
- 구현과 운영이 단순하고 DB 검색 기능을 활용할 수 있다.
- BitLocker나 다른 저장 볼륨 암호화가 없는 현재 조건에서는 DB 파일 유출 시 임베딩이 노출될 위험이 있다.

### 선택안 B — 보안 우선 RAM 검색

- 임베딩과 BM25 검색 자료를 암호화하여 저장한다.
- 서비스 시작 후 필요한 검색 자료만 RAM에 복호화한다.
- pgvector 대신 연속된 메모리 배열을 대상으로 벡터 검색한다.
- 서비스 시작 시간, 키 입력 방식, 메모리 사용량과 장애 복구 방식을 별도로 설계해야 한다.

개인정보·민감정보가 포함되고 BitLocker를 사용할 수 없다는 조건에서는 선택안 B를 우선 검토한다. 다만 실제 채택 전 검색 품질·속도·메모리와 운영 편의성을 시험해야 한다.

## 8. RAM 사용량 검토

Qwen3-Embedding-0.6B는 최대 1,024차원이며 32~1,024차원 출력을 지원한다. `float32` 1,024차원 벡터의 순수 배열 크기는 문단 하나당 4,096바이트다.

| 문단 수 | 임베딩 배열 예상 크기 |
| ---: | ---: |
| 10,000 | 약 39MB |
| 50,000 | 약 195MB |
| 100,000 | 약 391MB |
| 500,000 | 약 1.95GB |

BM25 색인, ID·메타정보, 라이브러리 오버헤드, OS·PostgreSQL·Ollama 사용량이 추가된다. 현재 예상인 수백 건 문서에서는 RAM 32GB로 시작할 수 있을 가능성이 높지만 실제 문단 수와 전체 프로세스 메모리를 측정해야 한다.

구현 시 다음 원칙을 검토한다.

- Python의 `list[float]` 대신 NumPy `float32` 같은 연속 배열 사용
- 전체 원문을 RAM에 상주시하지 않음
- 검색된 상위 10~30개 문단만 복호화
- 초기에는 정확 벡터 검색부터 측정
- 필요하면 1,024차원과 512차원의 품질·메모리·속도를 비교

Windows 페이지 파일과 메모리 덤프가 RAM의 평문 자료를 디스크에 기록할 수 있으므로, RAM 검색을 채택하면 해당 PC 운영 정책도 별도로 검토해야 한다.

## 9. API·입력·파일 처리 제안

- 모든 API에서 인증·역할·데이터 소유권을 다시 검사한다.
- SQL은 문자열 결합 대신 매개변수화한다.
- 상태 변경 요청에 CSRF 방어를 적용한다.
- HWPX·PDF는 확장자뿐 아니라 실제 형식을 검사한다.
- 파일 크기·압축 해제 크기·처리 시간과 메모리를 제한한다.
- ZIP 경로 조작, 압축 폭탄과 비정상 문서 파서를 방어한다.
- 원래 파일명을 서버 경로로 직접 사용하지 않는다.
- 문서 내용은 시스템 지시가 아닌 검색 자료로 처리하여 프롬프트 인젝션을 방어한다.
- 오류 응답과 로그에 원문·비밀번호·키·문서 암호를 넣지 않는다.

## 10. 감사와 보존 제안

다음 작업에는 사용자 ID, 시각, 대상과 결과를 기록한다.

- 로그인 성공·실패와 계정 잠금
- 계정 생성·비활성화와 역할 변경
- 관리자 원문 조회와 자료 내보내기
- 문서 등록·교체·삭제
- 평가 승인·반려와 튜닝 설정 변경
- 보존 기간 변경, 삭제·익명화와 키 교체

관리자가 사용자 질문·답변 데이터의 보존 기간을 설정하고, 기간 경과 후 선택 삭제 또는 익명화할 수 있어야 한다. 감사 로그에는 비밀번호·암호화 키·문서 공통 암호와 필요 이상의 원문을 기록하지 않는다.

## 12. 기존 문서와의 관계

`보안 및 계정관리.md`에는 BitLocker와 기관 계정 연동을 우선안으로 제안한 내용이 남아 있다. 두 기능을 사용할 수 없다는 사실이 확인되었으므로 해당 문서는 후속 결정이 끝난 뒤 수정해야 한다.

`design.md`, `시스템 구성.md`, `서버 설치 및 배포.md`에는 PostgreSQL + pgvector가 우선안으로 기록되어 있다. RAM 검색을 채택하면 저장·검색·시작·복구 흐름을 함께 수정해야 한다. 현재는 선택 전이므로 기존 문서를 즉시 확정안으로 변경하지 않는다.
