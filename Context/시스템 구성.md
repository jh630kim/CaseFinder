# 시스템 구성

## 1. 범위와 상태

내부망 사용자가 자연어로 사건을 설명하면, 서버에 등록된 HWPX·PDF에서 유사한 사건과 원문 근거를 찾아 보여준다. 문서 등록, 질문 처리, 사용자 평가와 개선을 한 대의 서버 PC에서 운영한다. 아래 기술 조합은 현재의 우선 제안이며, 샘플 문서와 실제 성능 검증 후 확정한다. 상세 요구사항과 대안 비교는 `problem.md`와 `design.md`를 따른다.

## 2. 신규 사건 저장

```text
담당자가 HWPX·PDF를 입력 폴더에 넣음
              ↓
일일 검사 작업이 설정 파일의 지정 시각에 새 파일을 찾음
              ↓
문서 처리 작업이 중복·암호를 확인하고 내용을 추출
              ↓
개별 사건 문서 또는 책자형 문서로 분류하고 사건별로 분리
              ├── 원본 파일 ─────────────→ 원본 보관 폴더
              ├── 사건 정보·본문 문단 ───→ PostgreSQL
              └── 문단 임베딩 ───────────→ PostgreSQL + pgvector
```

문서 처리 작업은 사건번호, 제목, 사건내용, 처분과 결정, 근거 문단, 원문 위치를 사건별로 연결한다. 성공한 원본은 보관 폴더로 옮기고, 중복·추출 실패·분리 불확실 사례는 구분하여 상태와 원인을 남긴다. 공통 문서 암호는 Git에 포함되지 않는 서버 설정으로 관리한다.

## 3. 사용

```text
사용자가 웹페이지에 자연어로 질문
              ↓
<span style="color:red">웹 서버가 질문을 접수하고 대기 목록 아래에 한 줄 요약을 추가
              ├── 질문자: 자신의 질문 내용과 상세 상태
              └── 다른 사용자: 개인정보·민감정보를 제거한 요약과 순서·상태</span>
              ↓
질문·대기 순서·처리 상태를 DB에 저장
              ↓
답변 작업자 1개가 접수 순서대로 질문을 가져옴
              ↓
정확한 조건 검색 + 한글 BM25 검색 + 임베딩 검색
              ↓
검색 결과를 결합하고 사건별 일치점·차이점을 비교
              ↓
Ollama의 답변 모델이 확인된 원문 근거로 답변 작성
              ↓
답변과 근거 위치를 DB에 저장하고 웹페이지에 표시
```

서버 전체에서 AI 답변 생성은 동시에 1건만 실행한다. 최대 20명이 웹에 접속할 수 있으며 나머지 질문은 순서대로 대기한다. 답변 완료까지의 최대 대기 시간은 정하지 않았다. 결과에는 사건번호, 사건내용, 결정 결과, 유사점, 차이점, 원문 근거와 위치를 표시한다.

검색 기술의 우선 제안은 한글 형태소 분석·BM25, 임베딩·pgvector, 순위 결합 RRF와 핵심 사실의 정확 검색이다. Fuse.js는 주 검색이 아닌 짧은 목록의 오타 허용 검색 후보로 둔다. 채택 이유와 대안은 `design.md`에 기록한다.

공통 GPU 작업 조정 기능은 사용자 질문의 임베딩·답변을 우선하고, 문서 일괄 임베딩·재색인·튜닝 평가는 배치 단위 사이에 양보하도록 한다. 중단한 배치 작업은 기록된 위치에서 이어서 실행한다.

## 4. 평가 및 반영

```text
사용자가 결과를 평가
              ↓
질문·답변·사용자 평가를 DB에 저장
              ├── AI가 평가 문항 변경 후보 작성
              │       ↓
              │   Excel의 변경 후보에 이전 값·제안 값·변경 이유·근거 기록
              │       ↓
              │   관리자가 검토·승인 → Excel의 승인 평가본 새 버전
              │
              └── 개선 작업이 검색·답변 변경안 작성
                      ↓
                  승인 평가본으로 변경 전후 결과 비교
                      ├── 기준 통과 → 설정 적용·이전 버전 보관
                      └── 기준 미달 → 변경 보류
```

문서 추출 오류는 원본으로 재처리를 시도한다. 원문에서 확정할 수 없는 정보는 평가만으로 임의 수정하지 않고 확인 대상으로 남긴다. 검색 순위와 답변 지침의 변경안도 기존 대표 질문에서 품질이 떨어지지 않는지 확인한 뒤 반영하고, 되돌릴 수 있도록 이력을 보관한다.

DB의 질문·답변·사용자 평가는 튜닝을 위한 운영 자료다. 하나의 Excel 파일에는 평가용 질문·정답을 `승인 평가본`, `변경 후보`, `변경 이력`으로 구분한다. 변경 후보마다 기존 내용과 제안 내용, 달라진 점, 변경 이유, 원문 근거와 관련 피드백을 기록한다. 품질 평가는 관리자가 승인한 버전만 사용한다.

DB에는 사건 정보와 질문 대기열도 저장한다. Excel의 승인 정답은 검색 색인이나 실제 사용자 답변에 제공하지 않는다. 승인 질문을 실행한 뒤 나온 결과를 기대 정답과 비교하는 검증 단계에서만 사용한다.

## 5. 구성 요소별 책임

| 구성 요소 | 받는 입력 | 담당 처리 | 결과와 저장 위치 |
| --- | --- | --- | --- |
| 담당자 | 새 HWPX·PDF | 입력 폴더에 파일 배치 | 입력 폴더의 신규 파일 |
| 일일 검사·문서 처리 작업 | 입력 폴더의 신규 파일 | 중복·암호 확인, 추출, 사건 분리, 임베딩 생성 | 원본 보관 폴더, DB의 사건 정보·검색 자료 |
| 웹 서버 | 자연어 질문과 사용자 평가 | 질문 접수, 대기·결과 상태 전달 | DB의 질문·평가·처리 상태 |
| 답변 작업자 1개 | 대기 중인 질문 | 검색, 사건 비교, 근거 기반 답변 생성 | DB의 답변·근거 위치·완료 상태 |
| 개선 작업 | DB의 사용자 평가와 Excel의 승인 평가본 | 오류 진단, 평가 문항 변경 후보 작성, 검색·답변 변경안 시험 | Excel의 문항 변경 후보, 검증된 설정과 변경 이력 |
| 관리자 | Excel의 변경 후보와 요청 시 변경 보고 | 질문·정답의 변경 전후와 이유·근거를 검토해 승인·수정·반려 | Excel의 승인 평가본 새 버전과 변경 이력 |
| 사용자 | 웹 화면 | 질문, 대기 상태·답변 확인, 평가 | 웹 화면에 표시된 결과 |

## 6. 저장 위치와 기술 선택 상태

원본 HWPX·PDF는 서버의 보관 폴더에 보존한다. 사건 정보·문단·임베딩·질문 대기열·사용자 답변·피드백·튜닝 이력은 PostgreSQL과 pgvector에 저장하는 방안을 우선 검토한다. 평가용 질문·정답과 관리자 승인 상태는 하나의 Excel 파일에서 관리한다. DB 조합과 검색 기술은 확정 사항이 아니며, 실제 환경에서 더 적합한 무료 이용 가능 대안이 확인되면 이유와 비교 결과를 제시해 다시 제안한다.

## 7. 확인이 필요한 부분

- 암호가 있는 HWPX와 책자형 HWPX의 추출·사건 분리 품질은 실제 샘플로 검증해야 한다.
- 서버 OS는 Windows 11로 확정했다. CPU와 저장 공간은 확인해야 한다. PostgreSQL·pgvector는 동일한 Windows 11 시험 환경에서 버전 호환성, 오프라인 설치, 임베딩 저장·유사도 검색과 백업·복원을 사전 검증하고, 폐쇄망 서버에서 반입 파일 무결성과 실제 설치·동작을 최종 확인해야 한다.
- 문서 등록·개선 작업이 질문 처리와 자원을 공유할 때의 응답 속도를 실측해야 한다. 무거운 작업은 이용이 적은 시간에 실행하는 방안을 검토한다.
- <span style="color:red">로그인 방식과 계정 연계, 일반 사용자·관리자 권한, 질문·원문 열람 범위, 다른 사용자의 질문 요약에 적용할 익명화·마스킹 규칙, 백업 위치·보존 기간은 아직 정하지 않았다.</span>
